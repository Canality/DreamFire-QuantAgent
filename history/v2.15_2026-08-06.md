## 4. WP1-D 正式稳定性

### Deterministic replay

- 八阶段顺序、snapshot identity、epoch reservation、single-flight 和 stale commit
  全部由服务端验证。
- replay CLI 不导入模型/网络，重算 snapshot/summary hash 后输出 20 个一致 receipt。
- 22 focused 通过；审查关闭 stale-epoch/single-flight race。

### Resource benchmark

- formal summary 记录每阶段耗时、角色 Provider usage、八张真实 ToolCard schema、
  进程树 RSS 和 observed concurrency；不可测字段保留 null。
- 聚合器要求恰好三份不同 summary hash 和相同 snapshot/manifest/schema identity，
  用 nearest-rank P95 判断耗时、RSS、并发和 token 降幅。
- 32 focused 通过；关闭 partial usage undercount 和自报 ToolCard identity 两项问题。

### Session teardown

- 依次 bounded 停止 team session、stream、Runner；失败写入 summary 并使正式
  verdict 失败，健康路径正常 `SystemExit`。
- 对上游拒绝取消的极端情况使用父 PID 绑定的 720 秒 worker watchdog，并终止
  递归 descendants；公开参数不能绕过 watchdog。
- 44 focused 通过；五轮生命周期反例全部关闭。

### Failure guard

- 同名工具按 trim 后 name 识别，第三次连续显式结构化失败输出
  `CONSECUTIVE_TOOL_FAILURE_LIMIT`；成功或不同工具重置，触发后诊断不可变。
- `tool_call` / `tool_result` 通过唯一 pending call-id/name 绑定，duplicate、unknown、
  missing、mismatch 和未完成结果失败关闭。
- formal Quant RPC 保持首次失败即关闭；该通用 guard 不是重试许可。
- 35 focused 通过；独立审查关闭四项 P1/P2。
