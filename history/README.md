# Dream Fire 版本历史

`history/` 保存已经形成真实项目版本边界的完整开发与验收记录，用于回归、
取证和复盘。它由 Git 管理、采用 **append-only** 规则，但**不是当前事实源**，
也不是当前开发路线或任务交接入口。

当前信息仍按以下优先级读取：

1. 当前运行事实：[VALIDATION.md](../VALIDATION.md)
2. 当前路线与验收契约：[DEVELOPMENT_PLAN.md](../DEVELOPMENT_PLAN.md)
3. 当前协作交接：[.claude/discussion.md](../.claude/discussion.md)
4. 历史版本、失败探索与旧数值：本目录

## 文件命名

版本文件固定命名为：

```text
v<major>.<minor>_YYYY-MM-DD.md
```

- 版本号必须对应真实项目交付边界，不能用工作包编号或计划文档版本代替。
- 日期是该项目版本形成日期。
- 文件开头必须写简介、commit/commit 区间和版本状态，随后保存完整改动、
  验收证据、失败尝试、限制及 superseded 判断。
- 没有 Git tag 时明确写“无匹配 tag”，不得把 commit message 当成 tag。

## 写入与纠错规则

1. 新版本必须先完成真实验收并更新 `VALIDATION.md`，再新增版本文件和索引，
   最后精简 README/discussion 中已关闭的时间线。
2. 已存在的版本文件不可重写、压缩或删除证据。需要纠错时，只能在文件末尾
   追加 `## Erratum — YYYY-MM-DD`，说明旧表述、证据和当前裁决。
3. 历史中的旧角色名、旧数值、失败命令和被推翻结论允许原样出现，但必须
   位于明确的历史快照/记录内；它们不能注入活动 Agent 身份。
4. 历史记录不能提升证据等级，也不能解除 `PROVISIONAL`、`BLOCKED`、
   `RESEARCH_ONLY` 或其他当前限制。
5. Git、`coordination/archive/` 和本机验收工件仍是原始证据；本目录是版本级
   导航与完整叙事，不替代原始文件。

## Agent 读取边界

- Codex 仅在回归排查、历史取证、版本总结或显式 history 任务中读取本目录。
- Claude 默认不加载历史文件；任务契约必须明确列出才可读取。
- 定位、实现和审查阶段只读取当前任务、当前事实源和当前路线，避免旧身份或
  旧数值污染决策上下文。
